This layer handles spatial understanding and robot positioning. For the Alpha robot, a 2D SLAM approach using slam_toolbox is employed to process LiDAR data and generate an occupancy grid map of the environment. Localization is achieved using scan-matching (rf2o) on the Alpha mapping robot, while the Beta robot uses a custom complementary filter that fuses wheel encoders and gyroscope data for motion estimation. Global path planning (A*, 8-connected with an octile heuristic over a dilated costmap) runs CONSOLE-side on the operator laptop, which feeds the robot one path leg at a time. The robot itself runs only reactive local navigation - ultrasonic-repulsion obstacle avoidance fused with the laptop's streamed heading bias - so the onboard layer never plans a full route. Robots that do not carry LiDAR reference the shared environment map provided by the Alpha mapping robot via the operations center state store.

High-level application logic is implemented in this layer. It includes object detection interfaces, hazard mapping functionality, and decision-making logic that governs robot behavior. This layer integrates perception results and sensor data to support intelligent system responses and mission-level behavior.

The top layer manages communication and user interaction. ROS publish–subscribe messaging is used to distribute data between system components, while a native PySide6 desktop dashboard provides real-time monitoring and visualization. This layer also supports data logging for analysis and debugging.

Each robot in the system runs a specific set of ROS nodes based on its assigned role. This node-based structure allows functional separation and simplifies system integration.

The Mapping Explorer Robot is responsible for environment mapping, localization, and autonomous navigation. It runs the following ROS nodes:

Hardware Interface Node – Interfaces with motors, encoders, and onboard sensors.

LiDAR Node – Publishes laser scan data for mapping and obstacle detection.

Laser Odometry Node (rf2o) – Estimates Alpha's motion by scan-matching successive LiDAR scans.

All Alpha motion estimation is laser-based (rf2o scan-matching); Alpha's wheel encoders are present but currently inactive.

SLAM Node – Executes the slam_toolbox algorithm to generate and update the environment map.

Navigation Node – Handles path planning, goal execution, and motion commands.

Together, these nodes enable autonomous exploration, mapping, and navigation within unknown environments.

The Visual Classifier Robot is dedicated to visual perception and object classification tasks. Its software configuration is optimized for camera-based sensing rather than full SLAM operation. The robot runs the following nodes:

Hardware Interface Node – Controls motors and basic sensor inputs.

Camera Node – Captures images from the Logitech C270 USB camera and publishes image streams.

Odometry Node – Estimates motion using wheel encoder and IMU data.

Localization Support Node – Estimates robot position relative to a shared map generated by the mapping robot.

Perception Communication Node – Transmits visual data and detection-related information to the central processing unit or dashboard.

This structure allows the robot to perform efficient visual perception while relying on shared spatial information, reducing hardware complexity and computational requirements.

The Environmental Sensing Robot focuses on monitoring environmental conditions and detecting potential hazards. It runs the following nodes:

Gamma is an ESP32 microcontroller with an embedded HTTP server and runs NO ROS nodes. Motor control endpoint - GET /control?dir=F|B|L|R|S drives the four motors.

Gas / telemetry endpoint - GET /telemetry returns JSON {d,g,x,y,a,rssi,uptime,last_cmd_age}; the MQ-5 gas reading is polled by the operations center at 3 Hz.

Local sensor task - samples the MQ-5 gas sensor and applies the alarm / clear thresholds onboard.

Gamma has no IMU/odometry localization on board; the operations center wraps its HTTP/JSON telemetry laptop-side.

This node configuration enables continuous environmental monitoring and supports system-level safety awareness.

Computationally intensive tasks, fleet monitoring, and operator control are executed on an external laptop running the PySide6 Operations Center. The following modules are implemented:

State Store – Main software module that maintains the shared map and coordinates telemetry.

YOLO Inference Worker – Deploys YOLOv8 (using fire.pt) in a crash-isolated child process for hazard detection.

Command Client / Esp32Link – Manages communication gateways to the Pi-based robots (via ZMQ) and ESP32 (via HTTP/JSON).

Log Collector – Aggregates diagnostics, incident alerts, and telemetry events for system evaluation.

Communication within the autonomous robotic system is designed to support reliable, real-time data exchange between the robots, the external operations center, and the operator. The communication architecture is implemented using a hybrid model: Pi-based robots (Alpha and Beta) run ROS 2 locally and communicate with the laptop via a custom ZeroMQ (ZMQ) gateway protocol, while the ESP32-based Gamma robot uses HTTP/JSON endpoints. The communication architecture of the proposed robotic system is designed to support reliable, real-time data exchange between the mobile robot, external computing resources, and higher-level monitoring components. The architecture follows a distributed communication model, where different types of data are transmitted using mechanisms best suited to their timing, bandwidth, and reliability requirements.

At the core of the communication architecture is local ROS 2 message passing for low-latency onboard control, combined with a custom ZeroMQ (ZMQ) gateway protocol for remote communication. ZMQ is employed to decouple the robots and the operations center, using PUB/SUB and ROUTER/DEALER patterns to distribute telemetry and dispatch commands. This architecture prevents standard ROS 2 DDS traffic from crossing the wireless WiFi link, ensuring scalability and link stability without requiring a complex ROS bridge.

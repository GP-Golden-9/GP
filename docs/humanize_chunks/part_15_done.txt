This layer is related to spatial perception and robot localisation. For the Alpha robot, the 2D SLAM approach is executed with the slam_toolbox, which processes the LiDAR data and generates an occupancy grid map of the environment. Localisation is performed by scan-matching (rf2o) on the Alpha mapping robot, while the Beta robot uses a custom complementary filter fusing wheel encoders and gyroscope data for motion estimation. Global path planning (A*, 8-connected with an octile heuristic over a dilated costmap) is done CONSOLE-side on the operator laptop, and feeds the robot one path leg at a time. While the robot itself only executes reactive local navigation, which is a combination of ultrasonic-repulsion obstacle avoidance with the laptop’s streamed heading bias, the onboard layer never plans a full route. The Alpha mapping robot provides the shared environment map of non-LiDAR carrying robots through the operations center state store.

This layer implements the high level application logic. It has object detection interfaces, hazard mapping features and logic to determine the robot's behaviour. This layer fuses perception and sensor data outputs to enable intelligent system response and behaviour at the mission level.

The top layer deals with communication and user interaction. System components communicate via ROS publish-subscribe messaging for data sharing and provide a native PySide6 desktop dashboard for real-time monitoring and visualisation. This layer also offers data logging for analysis and debugging.

Depending on the role of the robot, each robot runs a specific set of ROS nodes in the system. This node-based structure gives functional separation and makes it easier to integrate the system.

The Mapping Explorer Robot is responsible for environment mapping, localisation and autonomous navigation. It runs the following ROS nodes: 

Hardware Interface Node – Connects to motors, encoders and on-board sensors.

LiDAR Node – Publishes laser scan data for mapping and obstacle detection. 

Laser Odometry Node (rf2o) – Estimates Alpha's motion by matching consecutive LiDAR scans.

All Alpha motion estimation is laser-based (rf2o scan-matching). Alpha has wheel encoders but they are not used at the moment.

SLAM Node – Runs the slam_toolbox algorithm for generating and updating the environment map.

Navigation Node – Path planning, goal execution and motion commands.

These nodes together allow autonomous exploration, mapping and navigation of unknown environments.

Visual Classifier Robot is dedicated to visual perception and object classification. Its software configuration is more optimised for camera-based sensing than for full SLAM. The robot does the following nodes:

Hardware Interface Node – Motor and simple sensor inputs.

Camera Node – Takes images from the Logitech C270 USB camera and publishes the stream of images .

Odometry Node - Estimates motion using wheel encoder and IMU data.

Localisation Support Node – Estimates robot position with respect to a common map generated by the mapping robot.

Perception Communication Node – Sends visual data and detection information to the central processing unit or dashboard.

This structure enables the robot to perform efficient visual perception based on shared spatial information, which reduces the complexity of the hardware and the computational load.

Environmental Sensing Robot This robot is designed to monitor environmental conditions and detect potential hazards. It runs the following nodes:

Gamma is an ESP32 microcontroller with an embedded HTTP server and no ROS nodes running. Motor control endpoint - GET /control?dir=F|B|L|R|S Controls the four motors.

Gas / telemetry endpoint - GET /telemetry returns JSON d,g,x,y,a,rssi,uptime,last_cmd_age The operations center polls the MQ-5 gas reading at 3 Hz.

Local sensor task - reads the MQ-5 gas sensor and applies the alarm/clear thresholds on-board.

Gamma has no on-board IMU/odometry localisation. The operations center wraps its telemetry HTTP/JSON laptop-side.

This sort of node configuration makes sure that the environment is always monitored and increases the overall system safety awareness.

Computationally intensive tasks, fleet monitoring and operator control are done on an external laptop running the PySide6 Operations Center. The following modules are implemented: 

State Store – The main software entity which maintains the shared map and coordinates telemetry.

YOLO Inference Worker – Executes YOLOv8 (fire.pt) in a separate crash-isolated child process for hazard detection.

Command Client / Esp32Link – Communication gateways to the Pi based robots (over ZMQ) and ESP32 (over HTTP/JSON).

Log Collector – Gathers diagnostics, incident alerts and telemetry events for system evaluation.

Communication in the autonomous robotic system is intended to provide reliable exchange of data in real time between the robots, the outside operations center and the operator. The communication architecture is implemented as a hybrid solution: the Pi-based robots (Alpha and Beta) run ROS 2 locally and communicate with the laptop using a custom ZeroMQ (ZMQ) gateway protocol, while the ESP32-based Gamma robot uses HTTP/JSON endpoints. The communication architecture of the proposed robotic system has been designed to support reliable real-time data transfer between the mobile robot, external computing resources, and high-level monitoring components. The architecture is based on a distributed communication scheme in which different data types are transmitted with the most appropriate mechanisms for their timing, bandwidth and reliability needs.

The communication architecture is based on local ROS 2 message passing for low latency onboard control and a custom ZeroMQ (ZMQ) gateway protocol for remote communication. ZMQ is used to decouple the robots from the operations center, and telemetry and dispatch commands are distributed using PUB/SUB and ROUTER/DEALER patterns. This architecture avoids the need for a complex ROS bridge, keeping standard ROS 2 DDS traffic off the wireless WiFi link, ensuring scalability and link stability.
